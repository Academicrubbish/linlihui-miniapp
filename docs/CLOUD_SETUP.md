# 好邻小站：云端部署与家庭管理员

## 1. 部署前的状态

本地已配置微信 AppID `wxb2121357f142672b`，保留原来的 HBuilderX / uniCloud 支付宝云关联。新版不自动创建假账户或演示积分。H5 只用于布局检查，真实身份、截图选择请在微信开发者工具或真机验证。

## 2. 上传数据库及云函数

1. 在 HBuilderX 对已关联的 `uniCloud-alipay` 服务空间操作。仅上传新建的 `hl-*.schema.json` 和对应索引；不要覆盖旧业务表或导入测试数据。
2. 上传 `haolin-api` 和 `haolin-cleanup`（后者为云对象）。运行时使用 Node.js 18。
3. 在 `haolin-api` 云函数环境变量设置 `WEIXIN_APPID` 和 `WEIXIN_APPSECRET`。AppID 为上方值；AppSecret 从微信后台获取，不能写入前端、仓库、聊天记录或截图。
4. 确认 `haolin-cleanup` 定时触发已生效：每天北京时间 03:17，清理到期会话，以及处理完 90 天的已转账/退回订单截图。每次最多处理 200 笔；若积压超过此量，应增加执行频率或分批清理。
5. 微信隐私保护指引填入实际收集的微信身份、姓名、订单号与收货截图及其用途。确认相册选择能力可正常使用；不要求手机号、头像或地址。

表用途：

| 表 | 内容 |
| --- | --- |
| hl-customers | openID、备注姓名、余额、处理中预留积分 |
| hl-admins | 多管理员 openID、备注姓名、启停状态；无密码 |
| hl-sessions | 随机会话的哈希、微信身份和登录有效期 |
| hl-orders | 去重订单、状态、核实金额、应转金额、经办管理员 |
| hl-proofs | 受限大小的截图数据；客户端无直接读取权限 |
| hl-ledgers | 每次发放/扣减及当时余额，不提供修改/删除接口 |
| hl-logs | 提交、领取、取消、退回、转账、发放操作留痕 |

所有表均禁止 clientDB 直接读写。云函数凭微信 code 换取 openID；不能用客户端传来的 openID 或角色作为身份。不要给云函数配置无需鉴权的其他读写接口。

## 3. 录入妈妈、爸爸和自己的管理员权限

1. 每位管理员先用自己的微信打开小程序并填好姓名。
2. 在云数据库 `hl-customers` 中按姓名和界面的会员编号找对应记录，复制其 `openid` 和 `_id`。姓名可以重复，务必核对编号。
3. 在项目终端运行 `node scripts/admin-record.cjs`。按提示输入 openID 和管理员备注即可，不需要密码。脚本只生成 JSON，不会改数据库或上传信息。
4. 把输出 JSON 手动新增到 `hl-admins`。`_id` 必须等于对应 `hl-customers._id`（脚本按 SHA256(openID) 生成），不要让数据库自动生成另一个 ID。每人一条。记录只有 `_id`、`openid`、`name` 和 `enabled`。
5. 连续点击首页左上图标五下（相邻点击不超过 700ms），服务器核对微信身份后直接进入。未登记或被停用的微信即使知道入口也无法操作。

停用：将 `enabled` 改成 false，或删除对应管理员记录。每次管理请求都查表，包括金额事务内的权限检查，因此旧登录会话也会失去管理权限。改绑微信时，先停用旧记录，再按新微信的顾客记录创建管理员记录。

小程序登录会话有效 7 天；过期后需要重新取得微信登录凭证。“退出”仅返回客户首页，已绑定的微信下次仍可连点五下进入，不需要额外口令。隐藏入口只是减少普通顾客的界面干扰，不是权限边界；权限始终由服务端从微信换取的 openID 与数据库名单决定。

若曾部署过密码版：更新云函数与表结构后，在数据库手动删除旧 `password_hash`、`failures`、`lockedUntil`、会话中的 `passwordVersion` 和 `adminUntil` 字段。这些字段在新版不再读取，新版也不保存明文密码。

## 4. 转账如何避免出错

- 顾客仅填订单号与截图，管理员从截图核实实付金额。
- “确认金额，准备转账”在事务中预留 `min(实付金额, 余额−已预留积分)`。页面随即显示**本次应转金额**。此时账面余额不扣减。
- 只有经办管理员能点击“已转账，扣积分”；余额扣减、流水、订单已转账状态在同一事务内提交。
- 若请求超时，先刷新订单；已转账的不要再转一次。重复确认扣积分不会重复记账。
- 发放积分也有持久化操作号，网络中断后通过“核实上一笔发放”重试同一操作，不再新发一笔。
- 尚未转账可取消，释放预留；不自动超时释放，避免实际上已经转账但尚未登记的订单被另一人重复支付。
- 经办人不可用时：先线下核对是否实际转账，再由数据库维护者协调恢复该管理员登录处理。不要直接改余额/订单状态。此异常恢复没有前端入口。
- 退回订单可由原客户补交同一订单号，其他客户不能占用。订单号去除首尾空格并转大写后全局唯一。

## 5. 截图、容量与边界

截图每单一张，客户端尽量压缩到 600 KB 以下，服务端验证大小与 JPG/PNG 文件头，保存于禁止 clientDB 访问的凭证表。管理员鉴权后读取；不会产生公开图片 URL。微信端预览临时文件在退出小程序时删除。图片表可能增加数据库容量和流量，请关注用量；大规模使用时再迁移私有对象存储，不要直接改成公开桶。

处理完成的截图保留 90 天，未处理订单保留用于核实。定时清理删除的是图片，不是账本。退回订单补交可重新保存截图。涉及退款/更正和删除个人信息，由店主核实后处理；当前没有自动退款或任意调账入口。

## 6. 必须做的真机联调

两位管理员和一个顾客账号测试：首次填名；同名区分；截图上传/预览；发放 5 积分；提交 30 元已收货订单；管理员 A 领取后 B 不能转账；A 实际转账并确认后余额为 0；重复确认不重复扣款；退回补交；停用管理员后旧会话不能继续操作。没有真实云空间验证前，不用真实资金大范围推广。

本地测试以模拟事务验证业务，不代替云平台事务/索引部署与微信真机测试。确认环境变量、部署和首批管理员后，再进行上述联调。
