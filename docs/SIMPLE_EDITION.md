# 好邻小站：简化版实施约定（2026-10-21）

本文件是当前产品范围。README 和 MVP_IMPLEMENTATION_PLAN 中的早期多页方案属于历史，不再作为扩展功能依据。

## 用户已确认

- 客户只有一个首页，无底部 tab：备注姓名、积分余额、订单号与收货截图提交、业务说明。
- 姓名只供店主认人，账户以微信 openID 识别；同名使用会员编号区分。
- 提交结果直接在首页显示，订单金额由管理员看截图核实填写，不要求客户填写。
- 顶部标识连续点击五下，云端验证当前微信 openID 在启用的管理员名单内后直接进入，无需密码；管理员只做查人、发积分、处理订单。
- 独立管理员表支持妈妈、爸爸和子女等多个微信 openID，只存 openID、备注和启停状态。只能在数据库维护，没有新增管理员等前端接口，不保存任何密码。
- 1 积分对应 1 元补贴。实际补贴 = min(已核实订单金额，当前可用积分)。例如订单 30 元、积分 5，转 5 元并扣至 0。余额永不为负。
- 实际转账在线下完成，小程序仅记录结果，不接支付。
- 名称保持“好邻小站”。用户已确认采用去水印的人像花环图，微信后台更换等待服务类目和管理员扫码验证。

## 实施

1. 单页大字、宽按钮、少文案；姓名首次填写，之后可改；业务说明折叠。
2. 云函数通过微信 code 换取 openID，签发随机会话；所有数据权限由云端判断，客户端不提交身份或余额作为依据。
3. 使用独立 hl- 前缀表，避免破坏旧版演示方案及未知云端数据；所有表禁止客户端直接访问。
4. 金额统一以百分之一积分的整数存储。发放、预留、扣减、订单状态和审计日志用事务保证一致性，操作具备幂等性。
5. 多管理员线下转账采用领取处理：填写实付金额 → 锁定本次补贴 → 线下转账 → 已转账并扣积分。其他管理员只能看，不能重复转账。尚未转账可取消处理；不自动释放锁定金额，防止实际已转账但未记账时重复支付。
6. 收货截图以受限大小的图片数据保存在禁止客户端访问的独立凭证表，经鉴权读取，不使用公开图片链接。订单号全局去重，退回原订单后可原位补交。
7. 验证包括金额边界、重复提交、多人并发、伪造身份、未绑定微信、管理员停用/改绑/删除与会话失效、页面构建和手机宽度检查。

## 部署边界

代码与本地测试可以完成；真实微信登录还需服务端配置 AppSecret，上传云函数和数据库结构，录入管理员。凭据不进入 Git。没有云端配置时显示明确错误，不自动用演示积分冒充真实数据。
